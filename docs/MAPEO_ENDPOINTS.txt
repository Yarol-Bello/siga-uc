LEYENDA DE ACCESO
--------------------------------------------------------------------------------
[Público]    No requiere token.
[Autenticado] Requiere token JWT válido (cualquier rol autenticado).
[ADMIN]      Solo rol ADMIN.
[SECRETARIA] Solo rol SECRETARIA.
[DOCENTE]    Solo rol DOCENTE.
[ADMIN/SECRETARIA]  Roles ADMIN o SECRETARIA.
[ADMIN/DOCENTE]     Roles ADMIN o DOCENTE.
[ADMIN/DOCENTE/ESTUDIANTE] Cualquier usuario autenticado (la validación de
              propiedad del recurso se hace en el controlador).

Formato de respuesta (envoltorio uniforme en utils/response.js):
  { "success": boolean, "message": string, "data": any }

NOTAS TÉCNICAS
================================================================================
- Seguridad global: helmet, CORS (localhost:4200 y localhost:3000), JWT.
- Middlewares por ruta: verificarAutenticacion y verificarRol(...) en
  src/middlewares/authMiddleware.js.
- Validación de entrada con express-validator en rutas críticas
  (login, alumnos, recuperación de contraseña).
- Módulos con router.use(verificarAutenticacion): todos excepto authRoutes
  (las rutas públicas de login/recuperación están ahí).
- Manejo de errores: 404 global para rutas no encontradas + handler global
  de errores en app.js.
- Orden importante en rutas con parámetros fijos: en auditoriaRoutes.js,
  GET /api/auditoria/:id está después de las rutas fijas (/modulos,
  /estadisticas, /actas), por lo que no hay conflictos de coincidencia.
